# DoughTracker design language

## Audience and purpose

A personal expense tracker for its creator, with room for friends later. Help a
person understand monthly spending, investigate transactions, and trust the
freshness of connected accounts. The emotional goal is clarity and control.

## Personality

Calm, warm, analytical. Use direct, nonjudgmental language. Avoid playful copy,
gamification, neon colors, glossy gradients, and investment-terminal density.

## Visual direction

A quiet financial journal: warm ivory, forest-green accents, generous outer
spacing, and precise ledger rows. Newsreader headings give the page warmth;
Instrument Sans keeps controls and numbers readable. Numbers use tabular figures.
Light mode is the initial preview. Dark mode uses warm charcoal, elevated warm
surfaces, and softened green; both modes carry the same information hierarchy.

## Layout

Desktop web, starting at 1024px. A narrow icon rail expands over the page on hover
or keyboard focus and contains Expense Report, Transactions, and Accounts.
The expense report puts month/account controls
above a divided summary strip, then a wide spending chart beside category bars.
Recent transactions and top merchants finish the report. Transactions use a
full-width ledger and native dialog for details. Accounts group by institution;
connection setup is an inline panel, not an imitation of Plaid Link.

Sign-in uses an editorial split layout: generous Newsreader introduction on the
left, a compact labeled form on the right. Reuse the existing theme, focus, and
button tokens. Local and production share the same sign-in UI and session flow;
local authentication uses a mock service, not a separate demo experience.

## Motion and accessibility

Short opacity entrances and clear interactive states; honor reduced motion.
Target WCAG AA contrast, visible keyboard focus, labeled native controls,
semantic tables, an accessible text alternative for charts, and native dialog
focus management. Color never carries status alone. Desktop-only does not mean
disabling zoom or hiding functionality on a smaller viewport.

## Implementation

React/TypeScript/Vite and plain CSS, with the existing .NET API. No UI library is
installed; reuse native controls and small shared components. See
`design-tokens.json` for tokens and `docs/FRONTEND_FOUNDATION.md` for layout,
scope, Plaid mapping, and the next implementation steps.
